# 矛與盾：技術內容的說服、信任與認知防禦

#ai #persuasion #trust #critical-thinking #research

## 這是什麼

這是一組研究文件，起點是一篇宣稱「Claude Code 搭配 REA，在五分鐘內逆向分析路由器並修好 Wi-Fi」的社群文章。研究重點不是 REA 本身，而是文章如何影響讀者，以及讀者如何避免被誇大或誤導的內容帶往錯誤結論。

- **A（矛）**：研究內容如何被注意、理解、信任、採納，以及長期的專業信譽如何建立。
- **B（盾）**：研究自己如何識別內容中的證據缺口、信任越界與行動風險，避免誤信，也避免全面懷疑。
- **第二順位延伸**：未知系統轉換為受控 Adapter；不屬於本階段 A 主題，也不在此設計或實作 REA 工具。

這裡的「矛」指正當的資訊傳播與影響機制研究，**不鼓勵欺騙、偽造證據或操弄讀者**。「盾」是個人的認知防禦，**不等於 Agent 權限控管系統**；執行權限檢查是採取高風險操作時的後續防線。

## 核心結論

1. **流量、相信、信任、採用、長期依賴是不同結果**，不能以按讚或轉發推論說服成功。
2. 故事可協助進入問題；**關鍵主張仍須由可對應的證據支持**。
3. 信任必須標明對象、範圍與代價：相信一個 API 能被找到，不等於相信工具能安全修好所有設備。
4. **資訊可能部分正確，整體推論卻沒有根據**；辨識推論缺口是 B 的核心。
5. 防護目標是提高辨別能力，不是讓人什麼都不相信；查證、搜尋、AI 查核與警告本身也可能失效。
6. 所有文中的「雙循環模型」與「四層防禦」都是從文獻整理出的**研究用工作框架**，不是已完成效度驗證的心理量表。

## 證據規範

- 註明**原文觀察、原理推論、研究發現、未驗證假設**，不得混寫。
- 「技術可行」「案例成功」「成效由此造成」「一般情況適用」要各自舉證。
- 不能以某篇論文支持其未實驗的技術文章閱讀場景；跨領域套用應標成研究假設。
- 對來源不明、還沒有查證，以及已查證但證據不足，分別標記。
- 不從單一社群文章推斷作者有意欺騙、收受贊助或散播惡意程式。
