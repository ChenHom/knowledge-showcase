# B｜誤信、推論越界與認知防禦：研究結論及閱讀 SOP

#critical-thinking #misinformation #trust-calibration #research #playbook

## 這是什麼

B（盾）研究**自己如何避免誤信危險、誇大或誤導的內容**。這不是「全面不相信」，不是惡意程式掃描器，也不是 Agent 自動執行權限管理。它關注閱讀當下的判斷：作者說了什麼、證據能支持到哪裡、自己腦中補上了哪些未證實的結論，以及是否值得因此採取行動。

## 核心結論

1. **真實事實也可以導向錯誤的整體印象**。Paltering 研究的是刻意利用真實陳述傳達誤導印象，但不能在沒有意圖證據時替作者貼上此標籤。[R7]
2. **誤信與誤判真實內容都要防範**。只要提高懷疑程度，不代表辨別能力提升。[R10、R13]
3. 只標記部分問題內容，可能使沒標記的內容看起來已被驗證，形成「隱含真實效應」。[R8]
4. **上網搜尋不一定改善查證**；如果搜尋結果充滿同源或低品質資料，可能進一步誤信。[R9]
5. AI 查核也不是免責的外部裁判；研究發現某些錯誤 AI 標示可能讓新聞辨識更差。[R11]
6. 心理接種等事前訓練有改善辨別能力的研究支持，但效應受實驗條件、內容類型與衡量方式影響。[R12]
7. 閱讀技術文章最需要辨識的不是極端措辭，而是**從正確技術原理到超出證據的成效／安全／普遍性主張**，每個跳躍都需要獨立證據。

## 四層防禦：Claim → Evidence → Inference → Action

### C｜Claim：文章究竟提出哪些不同主張？

拆開「能分析 API」「實際取得控制權」「修復網速」「普遍可重現」「沒有資安風險」。它們需要完全不同的證據，不能被一句「AI 修好了路由器」合併。

### E｜Evidence：哪類證據能回答哪個問題？

| 證據類別 | 可能證明 | 不能直接證明 |
|---|---|---|
| 原理／文件 | 在某條件下技術可行 | 這次案例真做到了 |
| 程式碼／操作紀錄 | 特定實作／操作存在 | 產生了宣稱的成效 |
| 前後數據 | 觀察到數值差異 | 差異必然由某次修改引起 |
| 控制條件／重複實驗 | 特定條件下因果解釋更可靠 | 所有環境都適用 |
| 多環境獨立測試 | 部分普遍性支持 | 尚未涵蓋的環境也安全 |

要同時看**證據來源、獨立性、充分性、反面結果與時間／版本**。

### I｜Inference：列出中間缺少的前提

把文章推論寫成「A → B → C」，對每個箭頭提問：

- 結論與證據是否屬於同一件事？
- 是相關性、時間先後，還是真正有控制條件的因果證據？
- 是單一型號／案例，還是多條件重現？
- 有沒有只展示成功、沒有揭露失敗？
- 哪些結論其實是**自己推想**，作者並未明說？

如果無法證實，應標成「尚未確認」而不是「必然是假的」。

### A｜Action：相信內容，是否足以採取這個行動？

資訊可信，仍不代表照做是好決定。行動分級考量錯誤損失、不可逆性與外部依賴：

| 行為 | 必要查證 |
|---|---|
| 閱讀、了解原理 | 檢查核心主張與關鍵推論 |
| 引用、公開推薦、購買 | 追溯原始證據，尋找獨立確認 |
| 安裝不熟悉的程式、輸入帳密、給 Agent 權限、修改正式設定 | 另行審查來源、程式、權限、資料流與復原方案；沒有把握就不直接執行 |

最後一列是**採取行動時**的補充安全審查，而不是取代前面的認知防護。

## 三種容易誤認成「已驗證」的情況

### 1. 沒看到警告 ≠ 沒有風險

區分：
- **已獲充分支持**：證據能直接對應主張。
- **部分支持**：有技術依據，但成效或適用範圍有限。
- **證據不足**：已檢查，仍不足以判斷。
- **證據衝突**：有相當可信的不同結果。
- **已受可靠證據反駁**：核心主張不成立。
- **尚未查證**：還沒調查，不能當成安全或可信的認證。

「內容主張的證據狀態」和「照做的行動風險」要**分欄呈現**，不要合併為一個 AI 可信度分數。

### 2. 搜到十篇相同文章 ≠ 十份獨立證據

搜尋原始作者、原始程式、公開實驗、反面結果與不同團隊的驗證。不要只用文章標題關鍵字搜尋同立場轉述，避免低品質搜尋結果放大誤信。[R9]

### 3. AI 說有風險 ≠ 自己已完成判斷

要求 AI 先提供主張、證據出處與缺口，不要先給 35%、中高風險等數字。AI 的解釋也要接受同一套查證流程。[R11、R14]

## 閱讀時的分級 SOP

### 快速版（一般閱讀）

1. **我為什麼被吸引？** 是證據、驚人成果、熟悉的作者，還是正好符合我原本相信的事情？
2. **最重要的主張是哪一句？** 把它與次要技術細節分開。
3. **這個主張靠什麼證明？** 截圖、原始紀錄、官方文件或獨立實驗？
4. **我是否自行補上更大的結論？** 特別檢查因果性、普遍性與安全性。
5. **目前判斷到哪裡？** 部分可信、尚待查證，還是有足夠證據？
6. **我是否要採取行動？** 需要做事時提高驗證程度。

### 深入版（要引用、購買、安裝或授權）

- 先保留最初判斷，再進行查證，避免事後誤以為「早知道」。
- 用 SIFT 思路：先停、調查來源、尋找較佳報導／研究、追溯原始脈絡。[R15]
- 確認引述的來源**實際支援哪一個句子**；避免把權威來源作為不相干主張的背書。
- 對關鍵主張主動尋找反例與失敗條件，並核對時間、版本、樣本與測試條件。
- 明確寫出仍未知的內容；不能從「未發現」推論為「沒有」。
- 高風險操作另查套件來源、所需權限、網路目的地、憑證與回復途徑；先在低風險環境驗證。

## 防護為什麼也可能失敗？

- **警示疲勞**：看到太多沒有可操作解釋的風險標籤，可能逐漸忽略。
- **隱含真實效應**：只標部分文章造成其他文章看似被認證。[R8]
- **全面懷疑**：把所有 AI 技術文章都視為誇大，犧牲辨別能力。[R10、R13]
- **搜尋反效果**：搜尋結果集中在低品質同源內容。[R9]
- **AI 權威替代**：把對作者的無條件信任轉移給查核 AI。[R11]
- **介入成本**：要求主動思考雖可能降低過度依賴，也增加認知負擔。[R14]

因此，閱讀防護不是「一律不要相信」，而是**允許相信一部分、暫緩另一部分，並能隨證據更新判斷**。

## 研究練習：累積個人的誤信模式

每個案例記錄：最初印象 → 主要主張 → 吸引我的因素 → 原始證據 → 推論缺口 → 獨立查證 → 最後判斷 → 事後結果。

這個紀錄方法是應用建議，**尚無本研究自行實測其效益**。衡量時要同時追蹤：找到誤導的比率、將真實文章誤判為假的比率、是否能指出證據缺口、做出何種實際決策。

## 限制

心理接種、假新聞標籤、搜尋與 AI 查核研究，多以新聞、廣告或一般資訊環境為題，**不能直接宣稱其量化效果可套用在 GitHub README、AI Agent 教學或工程實作**。本系列「四層防禦模型」是文獻導向的實務框架，尚未進行對照實驗。
