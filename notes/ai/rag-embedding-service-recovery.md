# RAG 與記憶搜尋的 Embedding 服務復原

#rag #ollama #embedding #runbook

## 這是什麼

當 RAG 或 agent 記憶搜尋依賴的 embedding 服務停止，兩者可能同時失效。本筆記整理診斷、復原與驗證原則，適用於使用 Ollama、向量資料庫及容器的自架環境。

## 核心結論

- 先檢查 embedding endpoint、模型和網路，再確認 API、worker、向量庫及物件儲存；容器正在執行不等於應用已就緒。
- 沿用既有索引時，應保留相同模型版本、前處理、維度與索引設定。維度相同不代表向量語意空間相容。
- 服務移到本機時，容器與主機對 `localhost` 的理解不同。容器間使用服務名稱；僅需主機存取時，將埠綁定 loopback，避免公開暴露。
- 優先保留既有模型資料卷、原始文件與向量索引；不要為了恢復連線直接重建或刪除資料。

## 診斷與復原順序

1. 查看 API 和 worker 的啟動日誌，區分 provider 連線失敗、模型缺失與向量庫不一致。
2. 查明服務設定的 endpoint 和模型；確認網路可達與 embedding 服務可用。
3. 在所需的網路邊界啟動 provider，確認模型可載入，再重新建立必要的應用容器。
4. 驗證 readiness，檢查 embedding、向量庫、metadata 與物件儲存的依賴狀態。
5. 用標準搜尋入口驗證具代表性的查詢和來源，並檢查資料一致性；使用既有 gold set 評估搜尋品質。
6. Agent 記憶搜尋是另一條鏈路：確認其 embedding endpoint、索引狀態與實際搜尋結果，必要時依系統指引修復索引。

## 更新與回復

- 更新前記錄舊映像及模型識別資訊，保留既有資料卷與回復路徑。
- 更新後重新確認模型、維度、RAG readiness、搜尋結果與記憶搜尋；不得因服務啟動就宣稱檢索品質完全相同。
- 若原模型版本摘要無法核對，應明確標記限制；若更換模型，需規劃重新建立索引並重新校準檢索品質。

## 範圍與限制

本筆記是一般維運原則，不記錄私有主機位置或憑證。實際指令、服務名稱、備份和安全政策依部署環境為準。
